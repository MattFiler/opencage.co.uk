Introduction

The Debug Menu is a window drawn over the game by OpenCAGE's runtime utils, the plugin OpenCAGE puts in the game folder. It shows what the game is doing as it runs, from what each character senses and is about to do to the zones, nav mesh and collision your level was built with, and it has tools that act on the game: cheats, debug checkpoints, pausing and stepping, a free camera for filming, and a switch that keeps the game away from your saves.

Its tabs are in groups:

  • Overview: lines of information in the corner of the screen, such as the level, the zone you're in, the player's position and the frame rate.
  • Characters: every character the game is running, with what it senses and is doing, its orders and state, controls to change it, its animation and skeleton; the player, with cheats, teleports and their inventory; the input; and the alien, with what it has learnt.
  • AI: the characters' behaviour trees, the squads NPCs fight in, the trees' debug switches and log, a log of their state changes with breadcrumb trails, and a few tuning numbers.
  • World: what's under the crosshair, the zones streaming in, trigger boxes, doors and pickups, the nav mesh, cover and jobs, and the physics.
  • Scripts: a debugger for the level's scripts, their errors, triggers, progression and events, CAGEAnimations, debug entities, a profiler and the cameras.
  • Sound: what's playing and why, what the AI hears, the sound network, and tools to move the listener, make noises for the AI and play sounds.
  • Rendering: the game's own rendering switches and debug views, the lights, radiosity, post-processing, render targets and why something is or isn't drawn.
  • Performance: the frame and the renderer's limits, timing, memory and streaming.
  • Game: the game's flow and levels, saves and achievements, and tools: checkpoints, pausing and game speed, and actions on the AI.
  • Cinematic: the free camera, camera tracks, visuals, the HUD, the cast and screenshots, which take the place of Cinematic Tools.

Nearly everything in it has a name, so OpenCAGE and AI assistants can read it and switch it over Live Link (see Live Link & AI Assistants).

Turning It On

Press Launch Game on the main toolbar, tick Debug Menu at the top of the Debug tools group, and pick the key that opens it from the dropdown beside the box: F7 by default, with the same choices as Launch Game's other keys. Then press Start Alien: Isolation.

The runtime utils support the Steam, GOG and Epic Games Store versions of the game, so on other platforms the box is greyed out. The Debug Menu runs alongside the rest of the Debug tools: tick Live Link as well if you want OpenCAGE's script debugger or an AI assistant to work the menu (see Live Link & AI Assistants). Starting the game from Launch Game, or by saving with Options → Misc → Open Game On Save ticked, sets it up as it's ticked there, and it then stays in the game folder, so a game started from Steam has it too until OpenCAGE next starts the game without it.

The Debug Menu can't share its key with Hot reload, Unlock mouse or Possess characters while they're ticked: Launch Game says so and puts the dropdown back. It also warns you if you pick a key the Debug Menu's free camera uses (F8 turns it on and off, F9 takes a screenshot, and F1 to F3, Home, Delete, End, Page Up and Page Down act while it flies), because the free camera then goes without that key.

Cinematic Tools are now part of the Debug Menu. Launch Game no longer has an Enable Cinematic Tools box (hover over Debug Menu there and its tooltip says where they went): the free camera, camera tracks and visuals are in the Debug Menu's Cinematic group, and the separate Cinematic Tools program no longer comes with OpenCAGE. See Coming from Cinematic Tools for where everything went.

So are three more of Launch Game's old options. The Debug Menu also does what Enable UI Memory Overlay, Enable Debug Checkpoints and Enable Level Selection did, so they've gone from Launch Game: the UI memory overlay is a checkbox in Performance > Memory, the debug checkpoints are in Game > Tools, and any level can be loaded from Game > Game flow. See Removed Options.

Don't Write Saves

Under the Debug Menu box, Don't write saves keeps the game from writing to your saved games while it runs, so testing a level never changes them. It's a Debug Menu feature, so it's greyed out until Debug Menu is ticked. Ticked, the game starts with the Debug Menu's own Don't write saves switch already on, before the game first saves, so even the save a campaign level makes as it loads is kept back.

Like the Debug Menu itself, it stays in the game folder, so a game you start outside OpenCAGE afterwards writes no saves either, until OpenCAGE next starts the game without it. In the game, Game > Saves says what it keeps back, and turns it off or on as you play. Launch Game has more on it.

Using the Menu

In the game, press the key to open the Debug Menu, and press it again or Escape to close it.

Groups & Tabs

Along the top of the window is a row of groups in amber: Overview, Characters, AI, World, Scripts, Sound, Rendering, Performance, Game and Cinematic. Under the group in front is its own row of tabs. Overview and Sound have one tab each, so they show it straight away.

  • Opening on a tab. The window opens on the group and tab you left it on, Overview the first time.
  • Long tabs. Several tabs are made of parts, one under another with a line between them: scroll down for the rest. Headings with an arrow fold and unfold.
  • Selecting a character. Click a character in the Characters table, or pick one from the Character dropdown at the top of the tabs that work on one character, such as State, Control, Animation and Behaviour Tree. The selection is shared by every tab.
  • Hover for more. Most switches and buttons say what they do when you hover over them, and many say why they're greyed out.
  • Greyed out. A view that needs a level says No level running until one is. Anything your release of the game can't support is greyed out and says not available on this game release, rather than running and failing.

The Window

  • Moving it. Drag the window by its title bar, Debug Menu (F7 or Escape closes it), or by its bottom-right corner to resize it. It starts in the top-left corner. On a screen 1000 pixels tall or more, its text is drawn larger.
  • Your keyboard and mouse are the window's. While it's open, your mouse cursor is shown and the game doesn't see your keyboard or mouse, so you can click through the window without the player moving. A gamepad still reaches the game.
  • The game keeps running. To hold it while you look, tick Pause while this window is open in Game > Tools, or press Pause there. While the game is paused, changes that act on characters (the Control tab, the alien's setup, the AI actions) wait until it runs again or steps.
  • Notes along the top of the screen. A few things put a short line at the top of the screen, such as a save kept back or the scripts held at a breakpoint. They stack, so none covers another.
  • What lasts. Switches stay as you left them until the game closes, level loads included, with a few exceptions: the tree switches go back to unticked when a level loads, and a level change turns the free camera off.

Drawn Over the Game

Many tabs have switches that draw over the game: labels and view cones over characters, skeletons, the nav mesh, collision boxes, trigger boxes and more. They're drawn whether the window is open or not, so close it to play with them on screen.

  • Through walls. What the Debug Menu draws isn't hidden by the level. Most of it is only drawn out to a distance you can set, and the nav mesh has a height band to keep other floors out.
  • From any camera. It follows the camera the game draws from, the free camera and Live Link Camera included, so you can look down on a room from above.
  • Out of the window's way. The Info lines sit in the top-left corner, and move beside the window while it's open.

Overview

The Overview group has one tab, Info, so choosing the group shows it.

Info

The Info tab puts lines of information in the top-left corner of the screen, whether the window is open or not (while it's open, they move beside it). Tick the ones you want, or All or None:

  • Level: the level running.
  • Zone the camera is in: the zone the game has the camera in, by the name of its Zone entity, and how many of the level's zones are loaded. Zones loaded, by name lists them, handy when an area streams in wrongly (World > Zones has the rest).
  • Player position and facing, and Player speed: how fast the player is moving across the ground and up or down, over the last half second of game time.
  • Player health, stance and light: their health, whether they're crouched, hiding, in a vent or have the torch out, and how lit they are for the AI.
  • Camera position and direction, Frame rate, and the Game clock, with the speed it runs at while the game speed isn't 1.
  • Nearest alien: how far away it is, its branch, whether it's in the vents, and its menace. Characters: how many are alive and dead, and the nearest one.
  • Draw calls and primitives, GPU frame time and Memory and address space: the game's draw calls a frame, how long the graphics card takes over a frame (with GPU timing on in Performance > Timing), and the game's memory with how much of its address space is left. See Performance.

The frame-time graph from Performance > Frame goes under these lines.

Characters

The Characters group is about the characters the game is running, the player included: what they know and are doing, and tools that change them. Its tabs:

  • Characters: every character, with what it senses and is aware of, its health, mood and target, and where it's going, with labels, view cones and paths drawn over the game.
  • State: the selected character's orders, what its body is doing, and its state flags.
  • Control: change the selected character: what it may do, its mood and its health, or take it out of the level and spawn it again.
  • Animation: its animation trees, layers and clips by name, its skeleton, animation switches, and the level's animated objects.
  • Player: the player's cheats, health and teleport, how lit they are for the AI, and hiding, what's under foot and the objectives.
  • Inventory: what the player carries, and giving them more.
  • Input: what the game thinks is pressed.
  • Alien: the alien's menace, ambushes, sweep and vents, and what it has learnt.

Characters

The Characters table lists every character the game is running, the player first, with:

  • Name: the name the game gives the character. On many levels the game leaves every human with the same name (the Torrens crew are all Andy, and the alien is Alen), so look at the selected character's ids to tell them apart.
  • Class: Player, Alien, Android, Human, Security, Facehugger, Innocent, Heavy android, Tracker or Human (melee).
  • Distance from the camera, and Health.
  • Awareness / menace: how aware it is of the player, from Unaware upwards, or for the alien its menace.
  • Alertness, aggression, Mood and Branch: the behaviour branch it's in, such as an idle job, a search or an attack.

Click a character to select it. Its details appear under Selected, in sections you can fold:

  • Who: its name and class; its unique id, and the ids of the Character entity it was spawned from and the composite instance that entity is in; the behaviour tree it runs; and where it is.
  • State: its health, awareness of the player, alertness, aggression and mood, its branch and the one before it, and whether its enemies sense it. The alien shows its own awareness too, a character working towards spotting the player how far it has got, and any character what it's doing now: crouched, torch out, in the vents, stunned and so on. The player shows how long they've been hiding.
  • Target: who or what it's targeting.
  • Senses: each sense's level against its four thresholds (trace, lower, activated and upper), and which senses and view cones it's using.
  • Last known positions: where each sense last placed the player, and how long ago.
  • View cones and hearing: each of its view cones, with its type, length, width and height and whether the player is in it, and how far it can hear.
  • Path: whether it's moving and how fast, the path it's following and how far along it is, where it's going and how far it has left, and what its pathfinding is doing.
  • Flags and timers: the logic flags set on it, and the timers it has running.

With more than eight characters in the level, only those within 60 m of the camera are read in full: the table shows what it can for the rest, and a far character's details are read once you select it.

Drawing Over the Game

The switches under Draw over the game, at the top of the Characters tab, draw for the selected character only, or for every character with For every character ticked beside them:

  • Labels over heads: a label over each character with its name and class, its branch, its awareness, alertness and aggression (for the alien, its menace), what it's targeting, and a bar showing how close its senses are to noticing the player, against their thresholds. The player's label shows how lit they are for the AI, and is only drawn while the player is selected.
  • View cones: each of its view cones, from its head, coloured by its place in the character's set of cones. A cone the player is in is drawn thicker and filled in.
  • Hearing range: a blue circle at its feet, as far as it can hear.
  • Paths: the path it's following: the part already passed in grey, the way to the node it's heading for in white and the rest in blue, with the corridor it may walk in green and a yellow cross where it's going, labelled with the distance left.
  • Last known positions: a cross where each sense last placed the player, labelled with the sense and how long ago.

Labels, view cones, hearing ranges and paths for every character, seen from above the Torrens bridge with the game's camera following OpenCAGE's Viewport over Live Link. From up here the level isn't drawn, only what the Debug Menu draws.

State

The State tab shows the selected character's orders and what its body is doing. It only reads the game, so it changes nothing:

  • Orders: the command a script gave it (a command entity of the level's scripts, such as CMD_Follow, by its name there, with how far it has got) and the command its own behaviour tree's tasks gave it, each with the one queued after it. A script's command shows the ids of its entity and composite instance, so you can find it in OpenCAGE. Then the layered states its body is in (the overall one, moving and cover, with an arrow to the state it's about to go to, and dying), how it idles, and what has been asked of its body (moves, turns and the like) with how each went and where to.
  • Doing: the action it's in and the one before it, and the secondary actions layered on it, such as breathing, looking and aiming.
  • State flags: its alliance (and its alliance at spawn), the traversal it's on, and its stress; whether it takes no damage, doesn't react to hits, is very important or is untargetable, each with what set it (an action, an activity, combat, a script, a cutscene or debugging); then its 105 state flags, in the game's three sets. Tick Only those set, or type in the filter, to find one. A flag that changed in the last two seconds is drawn brighter.

Control

The Control tab changes the selected character through the game's own calls. The changes are made as the game next updates its characters, so nothing happens while the game is paused. The Last line at the bottom says what was done.

  • Motivations (NPCs only): the families of behaviour its behaviour tree may run (attack, stalk, systematic search, idle job, use cover, melee, retreat, panic and the rest), as tick boxes: untick one to keep the character out of that behaviour. Back to its defaults puts them back as they were when it spawned. Force idle (debug) is a debug motivation: the tree's idle branch runs ahead of everything else while it's on, where the tree has one.
  • Mood (NPCs only): the mood shown, and what each of the four layers moods are set on (the AI's, scripts', other code's and dialogue's) holds and for how long. Force mood holds neutral, scared, angry, happy, sad, suspicious or injured on the top layer until you choose (not forced). The face and voice follow the mood shown.
  • Health: its health against the most it can have. For an NPC, set it with the slider (at least 1), or press Damage 10% (it reacts as to a hit), Down to 1, Set on fire (it burns for 5 s) or Kill (as the game's own death actions kill). The alien can't be killed, as the game has no death for it, and a character set to take no damage doesn't die. Under them are its retreat and stun damage gauges against their thresholds, and its stress. The player's health is on the Player tab.
  • Spawning: Despawn takes an NPC out of the level, as a script calling despawn on its Character entity would. It's then listed under Despawned here with a Respawn button, which calls spawn on that entity: the game makes the character again where the level placed the entity (not where it was despawned), with a new unique id, once it has a free character slot and has loaded the character's assets. The list shows how far each has got. A script waiting on a despawned NPC may stall.

Animation

The Animation tab shows what the selected character's animation system is doing, with the names of its trees, nodes, clips and bones, which the game itself keeps only as numbers: the Debug Menu reads the names from the game's DATA\GLOBAL\ANIMATION.PAK the first time it needs them, so they follow a modded package too.

  • Character: its rigs (the gameplay one and the finer cinematic one, with their bone counts), its animation set and tree set, its stance, mood and equipment, which of its animation features are on, how often it's posed (characters far away are posed less often) and its ragdoll.
  • Layers: the eight layers its pose is built from (full body, general additive, breathing, look at, gun or tail, hand, face, and the final pose), with whether each is used, its weight, and how many trees and clips it has.
  • Trees: the animation trees running on each layer, with their weights. Expand one to follow its nodes down to the clips: each node's type, name and weights, what a selector picked and from which parameter, and for a clip node the clip, its time and length and its speed. Only nodes with weight hides the branches that contribute nothing.
  • Clips: every clip playing, split into those with weight and those without, with how far through each is, its speed, how many times it has looped and whether it's mirrored.
  • Movement, Reference locator and IK: the movement the animation extracts this frame, the velocities the character wants and gets, the point a matched animation (a kill, a door) is lined up to, and the IK solvers with their targets.

Skeletons

The switches at the top of the Animation tab draw over the game, for the selected character or, with For every character, every one:

  • Skeletons: each character's posed bones, the pose the game skins its mesh with, left bones blue and right orange. A character the game didn't pose this frame (far away, or out of view) is drawn dimmer. Bones near the camera, such as the player's own head, are left out. Pose drawn picks the final pose or any one layer's pose instead.
  • Bone names (the selected character), Bone axes and Helper bones (the head, hips, root, hands and feet the game tracks).
  • Velocity: arrows for the velocity the character wants, the one its animation gives and the one it ends up with. IK targets: where its IK is reaching for.
  • Tree and clip over heads: each character's full-body tree and the clip carrying the most weight.

The alien's skeleton over its mesh, seen through the game's camera placed by OpenCAGE's Viewport over Live Link.

Animation Switches

Further down the Animation tab are the animation Switches. Each changes one of the game's own steps in posing a character, for every character, or only the selected one with Only the selected character ticked:

  • IK off: feet are no longer placed on the ground, hands on what they hold or touch, or heads turned to look.
  • Velocity warping off and Turning warping off: the character moves and turns only as its animations do, so it can slide off its path.
  • Level of detail off: every layer at full weight, and the character posed every frame however far away it is (characters out of sight still aren't posed).
  • Reference pose: every layer is put in its rig's reference pose, the pose it was modelled in. IK still applies unless it's off too.
  • Ragdoll pose off: a character in ragdoll keeps the pose its animations give. Its body still falls.
  • Layers off: General additive, Breathing, Look-at, Hand and Face, each given no weight, as the game does for distance, so the layers under it show.

Under them, Reference locator has Draw the reference locator: while a matched animation (a kill, a door, a ladder...) lines a character up with a point, the point is drawn as axes with a line from the character. Layer weights by bone group shows how much each layer's pose counts on each group of bones, as the game combines the layers.

Environment Animations

Folded at the bottom of the Animation tab, Environment animations lists the level's animated objects, what PlayEnvironmentAnimation entities play, nearest the camera first: each one's rig, clip, time, state, distance and script entity (hover over the entity for its composite instance). Draw their skeletons and With labels draw their skeletons over the game, Within a distance of up to 300 m. Click one in the list to pick it out: it's drawn highlighted, however far away it is.

Player

The Player tab is in parts, from the top: the cheats, health and teleport; the player as the AI sees them, below; then hiding, what's under foot and the objectives.

  • Light: whether the player is dark, partially lit or fully lit for the AI, with the brightness the game measured and what it comes to through the AI's light curve, against the thresholds. The game measures the light at three heights on the player, each listed with the colour it found; tick Show the sample points to draw them in the game. The game turns the meter off for a while after the player is detected, and says so here.
  • Light meter tint: tick Tint the screen by light level to tint the screen by how lit each part of it is for the AI, blue where it's dark (the game's own debug view). Opacity sets how strong the tint is.
  • Stealth: the player's exposure, stance, cover and movement, whether they're hiding (and for how long), and which character is closest to spotting them, and how close. The alien's own progress is shown separately, as the game doesn't count it there.

The light meter tint: the dark parts of the room, where the player would be hard to see, turn blue.

Cheats & Teleport

The top of the Player tab has the player cheats:

  • God mode: the player takes no damage. It's the game's own debug switch, kept on every frame, since the game turns it off on some deaths and when a level script turns its own invincibility off. The alien's grab and the facehugger kill outright rather than doing damage, so they still kill: tick The alien can't grab the player as well, which sets every alien's own prevent grapples logic flag while it's on.
  • Untargetable: the AI doesn't choose the player as a target to attack, though it can still see and hear them. Invisible to the AI: the AI's senses no longer pick up the player; a character already hunting them keeps what it last sensed until it loses track.
  • Infinite sprint: the sprint never runs out. Infinite ammo: the player's weapons use no ammo from the clip when fired, so turn it on with ammo in the clip. Infinite items and Never run out of torch batteries are described under Inventory.
  • Health: a bar of the player's health, what's keeping them from taking damage (god mode, or the level's scripts), and their last hit. Full heal; Set health to a share of the most they can have, for checking injured animations and medikits; and Kill the player, the game's own forced kill that its scripted deaths use, so you can test the death and game-over screens on demand (god mode is lifted for it).

Teleport moves the player to a position you type (Copy puts where they are now in the box and on the clipboard), To the camera (fly the free camera there first; the player's feet go where the camera was, so expect a short drop), To the crosshair (the point under World > Inspect's crosshair), or Back to where the last teleport took them from. It's done the way the game puts back a character that fell out of the world, at the end of the next physics frame. Somewhere with no floor loaded, the player falls, and the game puts them back where they last stood.

Hiding, Under Foot & Objectives

The bottom of the Player tab:

  • Hiding: whether the player is hiding, for how long, and whether in a vent; where the AI looks for a hiding player (the point the script of the hiding place they last used sets, which the alien goes to when it comes to pull them out), drawn with Draw where the AI looks for the hiding player; for each alien, whether it's going for the hiding player and whether the player won the struggle; and what the alien has learnt about hiding: whether it searches lockers and under things yet, and how often the player has hidden from it.
  • Under foot: what's under the player's feet, from the four rays the game casts down from them: the sound material the footsteps use, the physical material and whether it's walkable or climbable, the zone that puts them in and whether it's visible, whether they're in water or off the ground, where they're supported and the drop below their feet. A table gives the row of the level's collision map each ray hit, with its entity, composite instance and zone. It's a quick check of OpenCAGE's collision and material changes in place: a wrong footstep sound, or a zone that streams out underfoot, shows up here. Draw the support point and the surface draws them.
  • Objectives: the primary, secondary and exit objectives as the player's inventory holds them, with their text in the game's language, and the motion tracker's objective and how far it is by its route. Draw the motion tracker's route draws that route. Show the objective popup shows the game's objective popup with any text or text key you type, and Popup beside an objective shows it for that one; the objectives themselves aren't changed.

Inventory

The Inventory tab shows and changes what the player carries. Everything here changes what the next save holds, so while Don't write saves is off an amber line at the top says so: turn it on first to keep a campaign save clean.

  • Current weapon: the weapon in the player's hands, its ammo type, clip and the ammo carried, overheating and charge where it has them, and the torch with its battery. Fill this weapon's ammo gives every ammo type it takes, as much as can be carried; Fill ammo for every weapon carried does it for all of them.
  • Inventory: slot by slot, each item with its kind, its count against what can be carried, and whether it's in hand, selected or locked, with a Fill button. Top up everything fills all but the weapons.
  • Give: the game's own item list, so modded items are in it too, with a filter. Give a count, or Fill up to what can be carried; double-click an item for a batch. Items are given as the level scripts' AddToInventory gives them: only with a free slot, and capped at what can be carried. Give all gives medikits, flares, every IED and crafting part as many as can be carried, and every blueprint. Give every weapon adds each weapon with its ammo filled; it hasn't been tested in the game yet, so a weapon may not land in the weapon wheel as a picked-up one does.
  • Blueprints and keycards: which blueprints are available, with Give every blueprint (the game's own call, which also marks them collected), and the keycards, with Collect every keycard.
  • Gating tools: the key, axe, crowbar, gas mask, cutting tool, hacking tool, rewire tool and cable clamps, ticked when carried, each with its level (type one and press Enter). A hack's or a rewire's difficulty follows the tool's level, and the tab shows the hardest hack each hacking tool level opens. Give every tool at level gives them all, at 50 by default, which opens every hack.
  • Infinite items: using up an item (throwing, placing, using or equipping a flare, an IED, a noisemaker, a medikit...) leaves as many in the inventory, as one more is added just before the game takes one. It hasn't been tested in the game yet. Never run out of torch batteries keeps the inventory full of them; the battery in the torch still drains, as that's up to the level's scripts.

Input

The Input tab shows what the game thinks is pressed: every action of the player's input, or from the dropdown the menus' or the debug input, with its state (pressed, held, released, toggled or disabled), each analogue value that isn't at rest, and whether the input is enabled, movement let through, and the input locked by the interface. Every action lists those at rest too.

While the Debug Menu is open it has the keyboard and mouse, so the game sees nothing from them: tick Show what is pressed over the game and close the window to watch it as you play, or use a gamepad.

Alien

The Alien tab shows the alien's own state, once it has spawned:

  • Its setup (its difficulty set-up, such as MODERATE) and the branch it's in.

What the Alien Has Learnt

Under the alien's state, the Alien tab has three more parts:

  • What the alien has learnt: the difficulty, the lowest played, and the furthest mission the alien has spawned in this run. Then its tricks (threat aware, closes in through the vents, kill traps, flanks, flanks from threat aware, ambushes, searches lockers and searches under things), each with whether it's unlocked, what its behaviour tree's own check answers, and the counter that unlocks it against the number it unlocks at on this difficulty: how many times the alien was driven off with fire or searched for the player, or the player hid from it or hid in a deep crouch (ambushes only come with a stage). On Nightmare every trick is on, whatever is unlocked. Tick or untick a trick to give it or take it away, or Set a stage, one of the alien's four learning stages: Naive, Threat aware, Getting sneaky and Really sneaky.
  • Setup and the director's numbers, with an alien in the level: switch the alien's setup to any of the level's, as NPC_AlienConfig does, and read what the game's director makes of the setup at the difficulty played: how fast the menace gauge fills, when a menace counts, the sweep box and how fast the sweep widens and narrows, when the alien is drawn to the vents, how long it sweeps backstage, and the most menaces before it withdraws.
  • Draw the alien to a point: every alien hears the player moving at the point under the crosshair (World > Inspect), at the camera or at the player, past its Suspicious threshold (it comes to search) or its Alerted one (it comes to hunt). It's greyed out with no alien in the level.

What the alien has learnt belongs to the game rather than to one alien, so it can be changed with no alien in the level, and every alien uses it. The game keeps it in memory only, never in a save: the level scripts set a stage at points in the campaign (NPC_SetAlienDevelopmentStage), and the alien's first spawn in one of the first three missions starts it over, so a change lasts until then, or until the game closes. A trick you take away comes back the next time its counter counts, if the counter is past its number.

AI

The AI group shows how the characters decide what to do. Its tabs:

  • Behaviour Tree: where the selected character is in its behaviour tree, node by node.
  • Squads: the NPCs that fight together, their objectives and their cover.
  • Tree Switches: the behaviour trees' own debug switches.
  • Tree Log: what the trees' debug actions log.
  • State Log: the characters' state changes, and breadcrumb trails of what each did where.
  • Tuning: five tuning numbers the game reads as it runs.

Behaviour Tree

The Behaviour Tree tab shows where the selected character is in its behaviour tree, the same trees you can open in the Behaviour Tree Editor:

  • Tree: the tree it runs, and its outer branch (and the one before it).
  • Active path: the nodes it's running, from the root down to the leading node, each with its name, what a condition answered, and whether it's running a child or running itself. Hover over a node for the tree file it came from, its number in that file (as the Behaviour Tree Editor numbers them) and its other attributes.
  • Active branches, and Recent events: the branches it has switched on and off and the actions that succeeded or failed, newest first, with how long ago.
  • This character's debug texts and asserts: what its tree's debug actions have logged (see Tree Log).
  • Tree files loaded for this level: each tree file the level loaded, with its node count.

Tick Show over characters to draw each character's leading node, outer branch and latest debug text over it in the game (the nearest twelve at once).

The node names are noted as the level loads its trees. If a level's trees ever loaded before the Debug Menu could follow them, the tab says so: its nodes show only their class, and the Tree Switches tab has no switches for that level.

Squads

The Squads tab shows how the game organises NPCs that fight together:

  • The group of NPCs: every NPC the game's group holds (the alien is never part of it), with its awareness of the player and the highest it has reached, its objective (a move, its start, cover or a safe point) and where, its nearest safe point, its target and how far away, and whether it may melee and pursue. Under it, how many safe points the level has.
  • Squads: the squads the game makes of them while they fight together, each with its aggression, members and how many are searching, its centre, how its cover search is going, each member's cover request with the cover slot it asked for and the one it was given, and the targets they share.

Squads and objectives draws an arrow from each NPC to its objective, labelled, and each squad's centre with lines to its members; Safe points draws the level's safe points as green rings. With no NPCs fighting together, there are no squads and the tab says so.

Tree Switches

The behaviour trees have debug switches of their own: the DebugMenuLinkTest and DebugMenuLinkItem nodes in the Behaviour Tree Editor. The Tree Switches tab lists those in the level's trees, with each one's default and the trees it's in. Tick a switch to make its test go the other way from its default; an action with the same label sets it back to its default when a tree reaches it, so a one-shot switch, such as Force_Breakout, unticks itself.

The switches act for every character, or only for the selected one with Only for the selected character chosen (the Character dropdown is greyed out until it is). Untick all puts them all back, and they all go back to unticked when a level loads. The shipped trees have 18, among them Disable All Aliens, which sends the alien into an idle action until you untick it, Force_Backstage_Stalk, Allow Hit And Run, Force Android Idle, Human Direct Control and Force Idle.

Two of them need a word. Allow Hit And Run is on by default, so ticking it turns hit and run off. Alien Gamepad control, Android Direct Control and Human Direct Control lead to branches that also need the game's own free camera (not the Debug Menu's), which the game never turns on, so on their own they do nothing: Possess Characters does that job.

Tree Log

The behaviour trees' DebugString action logs its text whenever a character's tree runs it, and the Assert action its message. The Tree Log tab lists them for every character, newest first, with how long ago, the character, the text, the node it came from and how many times it repeated (a line counts its repeats until a second goes by without one). Clear empties it.

The shipped trees use no DebugString, and their five asserts only fire in rare cases, so the log is for trees you've edited: add a DebugString to a branch in the Behaviour Tree Editor to see when characters reach it.

State Log & Breadcrumbs

The characters' state machines (moving, cover, dying, the weapon and shooting) still hand a line to a logger from 29 places in the game, which then throws it away. With Log state changes ticked, the State Log tab keeps each one: the time, the character, the machine, and the change from one state to another, with what it wants or the state it's in alongside. Only the selected character narrows it to one, the filter finds a character, machine or state, and Clear empties it. Nothing is logged until it's ticked.

Breadcrumbs are a trail of what each character did where. Draw breadcrumbs draws, for the selected character or with For every character every one, a trail of where it went, and a labelled crumb wherever its behaviour tree branch, awareness, mood, body state, action, script command or health changed, where it went into or out of the vents, and where it died (and each state change, with the log on). They fade over a minute, or as long as Kept for says, from 10 seconds to 10 minutes.

Tuning

The Tuning tab has five numbers the game reads every time it uses them. Each is given here with the game's own value:

  • Human and android melee range: how close a human or android must be to land a melee attack (2.5 m).
  • Android melee spot kept for: how long an android keeps to the melee spot it chose round its target before choosing again (60 s).
  • Android grapple: delay before it hurts: how long an android's grapple holds the player before it starts doing damage (1.5 s).

World

The World group shows the level around the camera and the player. Much of it is what Save and Build bakes, as the game loaded it, so it's the place to check a rebuilt level. Its tabs:

  • Inspect: what a crosshair in the middle of the screen is on, from its row of the level's collision map to the model drawn there.
  • Zones: the zones streaming in, and why each view is in its zone.
  • Overlays: trigger boxes, doors, splines and pickups drawn over the game, and measuring rings.
  • Navigation: the nav mesh, its barriers and doors, the AI's path searches, and who can get where.
  • Cover & Jobs: the level's cover and the AI's jobs.
  • Physics: static collision, bodies and capsules, physics systems, and the rays the game casts.

Inspect

The Inspect tab tells you what the camera is looking at. Tick Crosshair inspector and a crosshair appears in the middle of the screen: a ray is cast from the camera along the way it looks, through the game's own queue of rays (the one its zone streaming, footsteps and AI sight use), so the answer is what the game itself finds on that collision layer. The game works the ray out during its next frame, so the answer is a frame old, and no ray is cast while the game is paused (the last answer is kept while the camera still looks the same way).

  • Label (the distance and what was hit, under the crosshair), Model box, Collision box and Glow (the model hit drawn with the game's own glow for usable objects) show it in the game. Freeze keeps the answer while the camera moves away.
  • Ray layer: the collision layer the ray tests against. The surface-test layer is the default (the one the zone and footstep rays use); the list also offers what AI sight uses, ballistic collision, triggers, sound, door blockers, the player's and the rest. Ray length goes up to 500 m.
  • Under the crosshair: where the ray hit, how far away and the surface's normal (Copy puts it all on the clipboard), then everything the level's collision map says about what was hit: its row and flags, the script entity and composite instance it belongs to (with the composite's name and the instance's path from the level's root, as OpenCAGE addresses it), its zone, its render and physical material (the physical one decides footsteps and impacts), the static collision it's stored as, and the model drawn in its place, with its elements, materials, textures and LOD ranges, its environment map, radiosity slice and tint. Something with no row, such as a physics body, shows the body instead.
  • Any row of the collision map: look any row up by its number (The one hit fills in the row under the crosshair), and tick Draw it to see where it is.

Other tools use the crosshair too: the Player tab's To the crosshair, Draw the alien to a point, the Navigation tab, and OpenCAGE's Select Entity Under Game Crosshair in the composite display's Script Debugger menu, which selects the entity under the crosshair in OpenCAGE.

Zones

The Zones tab shows the level's zones as the game's zone streaming keeps them:

  • The summary: how many zones are loaded, streaming in and wanted, the links between them and how many are open, the zone the camera is in, whether streaming has stopped because it ran short of memory (nothing more loads until zones unload), what is loading or suspending now, and whether a script holds the screen faded out.
  • Every zone, with its priority this frame (a zone a view is in gets 100, and its neighbours through open links that less the link's cost; zones at 80 or more are wanted), which views see it, its state (loaded, loading or unloaded, suspended, or asked to load or unload by a script), its links, how many of its entities are still loading, and how many composite instances live in it. Loaded only, Wanted only and a name filter narrow the list.
  • Choose a zone for its id, the Zone entity that made it, its links (to which zone, open or closed, locked, their cost and the entity that made each), the zones it's excluded with, and the composites in it. Under the list are every link, and the viewpoints the views registered this frame.

Why each view is in its zone: a view whose camera follows a character (the player's camera) is handed the zone under the player's feet; any other casts a ray 500 m straight down from the camera, and the collision map row it hits gives the zone. The tab names the row each view's ray hit, with its entity, composite instance, layer, flags and zone, and the rows under the player's four foot rays. A wrong zone on a rebuilt collision row, or a piece of collision under the camera that shouldn't be there, shows up here as the reason the zones around the camera never stream in. Draw the zone rays over the game draws them (Every view for all the views, not only the first).

Overlays & Measuring Rings

The Overlays tab draws script entities over the game, each kind with a switch: the player's trigger boxes (PlayerTriggerBox) and use trigger boxes (PlayerUseTriggerBox), doors with the zone link they open, splines with their points and direction, and the interaction points the game keeps for pickups, weapons, ammo, doors, computers and save points, with their quantity.

  • Colours: trigger boxes green, use trigger boxes blue, disabled ones grey (Only enabled boxes leaves those out). A box flashes yellow as the player walks in and orange as they walk out. Doors are yellow closed, green open, cyan opening or closing and red locked. Interaction points have a colour per kind.
  • Labels give a box's composite, state, collision row and zone, and how long ago the player last walked in and out; a door's state, whether it's locked or scripted, and its zone link with that link's state; an interaction point's name, kind and quantity. Labels are drawn within Labels within (12 m at first), and everything within Distance (25 m), nearest first.
  • Found in the level lists what was found, nearest the camera first, one kind at a time. The level's entities are looked through again every few seconds while any of these are on or the tab is open, so something a script has just spawned shows up a moment later; Look again looks at once.

Measuring rings, at the bottom of the tab, draw up to four rings on the ground (2, 5, 10 and 20 m; Default radii puts those back) Around the player, the selected character, the point under the crosshair, or a point you drop with Drop a point here, with the distance along the ground to each character inside: handy for checking the ranges the AI works to.

Navigation

The Navigation tab shows the nav mesh the game loaded for the level's current state, as the game holds it: the quickest way to check what OpenCAGE's nav mesh bake wrote. Its sections fold:

  • Nav mesh: whether one is loaded and which state it came from, its polygon, vertex, off-mesh connection and barrier counts, and how often it has changed since (doors). A level whose state's nav mesh file is missing, of the wrong version or won't load runs with no navigation at all, silently: here it says NO NAV MESH LOADED. Tile header and ids has the rest of the header (walkable height, radius and climb, the bounds...).
  • Drawing: the polygons near the camera (or Around the player), filled and outlined, coloured by markup (normal, backstage, expensive), the classes of character they let through, height (standing, crouch, deep crouch), enabled, the barrier they belong to, traffic (how long since a character pathed through), or a flood's reach or islands; the barrier polygons; off-mesh connections as arcs coloured by kind, with an arrow on one-way ones; traversals; and polygon numbers. Distance, Height band (to keep other floors out), Most polygons and Fill set how much is drawn and how.
  • Polygons under the player, characters and crosshair: the polygon under each, with every flag decoded (enabled, the classes it lets through, its height and markup, the door barrier it belongs to, its links, when it was last pathed through). Show it highlights one, and Flood from it floods from it. Each NPC shows the polygon under its feet beside the one its own movement says it's on.
  • Barriers and doors: doors are barriers on the nav mesh. The level's barrier table (each area, what it lets through now, the door, the barrier entity, how many polygons it cuts out, its collision row and zone); a door audit against the sound network, since a door sets its nav barrier and its sound doorway by the same id, so a barrier with no doorway, a doorway no barrier has, or the two disagreeing (open for the AI, shut for hearing) shows up here; and a log of every change a door makes.
  • Off-mesh connections and Traversals: those near the camera, nearest first, with their entities (vaults, ladders, vents...), and what the player can climb or vault now.
  • Path searches: the AI's path searches as they finish, with who asked (movement, cover, a path length, a route check...), whether they succeeded, failed or only got part of the way, and where they started and ended. The failed and partial ones can be drawn.
  • Who can get where: floods the mesh from the player, the crosshair, the camera or the polygon shown, with the game's own rule for what a class of character may cross (with or without the vents and deep crouch), showing what's reached and splitting the mesh into islands, largest first.
  • Path tester: runs the game's own path search between two points (the player, the crosshair, the camera or the selected character) for a class of character, and draws the path it finds.

Debugger

OpenCAGE's script debugger stops the level's scripts, and the game with them, just before a method is called on an entity you've set a breakpoint on. Breakpoints are set in OpenCAGE: right-click a node in a composite's flowgraph and choose Set Breakpoint, or press F9 over it, with the game started with both Debug Menu and Live Link ticked. The Debugger tab shows the same thing from the game's side:

  • Whether the scripts are held: Scripts running, or held at a breakpoint, held after a step, or paused by the debugger. While they're held the game is paused as it is for its pause menu, and a line along the top of the screen says where they're held, so the game doesn't just look frozen.
  • Continue lets the scripts go on. Step makes the held call and the rest of the calls due at the same moment (one round), then holds them again. Step frame lets one whole frame of the game run. Pause scripts holds them now, as a breakpoint would.
  • The held call: the method, the entity it's called on, the composite and instance it's in and the path of instances to it, when it was due on the scripts' clock, and the calls that led to it, latest first. A call nothing in the scripts made (the game, or a timer, queued it) says so.
  • Breakpoints: each one set, with a box to switch it off and on, how many methods it stops on, how many running instances it's in (not in when there are none; hover for why), how often it has been hit, and Remove. Errors

The game still checks that the level's script entities are set up properly, and words what it finds: a pickup spawner that names no item, a door with no animation, a speech entity with nothing to speak through, an animation set missing the animation asked for, a zone link the wrong way round, a Global Event value out of range, and so on. The game makes those checks but never tells anyone. The Errors tab lists every failed check (Check, in amber) and error (Error, in red), one line per message and entity, with how many times it has happened and how long ago it last did:

  • Click a line to see it under Selected: the message, the entity and its ids, how many times and when first and last, with Copy ids and Copy line. By message counts each message across every entity, and Every occurrence lists them one at a time instead.
  • Keep script errors (on) notes them; Show new ones on screen (off unless you tick it) puts each new one at the top of the screen for six seconds, whether the window is open or not. Clear forgets them.
  • Dropped calls: methods called through links that the game threw away without running, because the entity that started their chain of calls had been shut down (its zone unloaded, or it was deleted) by the time they came due. That's often meant to happen, but a delayed link that never fires shows up here, with the method, the entity it was for, the entity that started it and how long ago.

The grey line at the top says how many of the game's 173 checks and errors are being watched; on a release of the game where some aren't where they should be, it says how many were left alone. Both lists start afresh when another level loads.

Triggers

When an entity fires an output, each method its links call is queued, and runs when it comes due. Waiting calls lists those that haven't run yet, soonest first: how long until each is due, the method, the entity it's called on and the call that queued it, with the start of its chain (hover over the time for the link's delay). A link with a delay waits here; entities that time things themselves, such as delays and timers, don't show. Keep reading (on) reads the queue four times a second, and Read now once.

Trigger counts: tick Count to count every call the scripts run, by method and entity, busiest first, with how many ran in the last second and in all. An entity calling itself in a loop, or a timer firing far more often than you meant, shows at the top.

Progression

Rendering Switches

The game has rendering switches of its own, and the Rendering tab lets you flick 69 of them while the game runs, in groups you can fold:

Lights

The real-time lights, to see what each does to a scene:

  • The lights drawn this frame, nearest first (or with Every light of the level, all of them): each one's type, mover index, colour, reach, features (shadow, gobo, specular, volume...; hover for them in words), state (drawn, with a shadow map, wanting a shadow map but over the budget, feeding the bounce light) and distance. Performance

The Performance group shows how hard the game is working and how close it is to its fixed limits: when a limit is full, the game quietly leaves out what comes next, which explains lights, shadows, effects and models that go missing in a busy custom level. Its tabs are Frame, Timing, Memory and Streaming. Nothing is measured until one of them is shown, or one of their switches, Info lines or commands is used. The Info tab has three lines from them: draw calls and primitives, the GPU frame time, and memory and address space.

Frame

  • Frame time: the frame rate and frame time over the last second, the fastest, slowest and 1% slowest of the frames kept, and a graph of them. Graph over the game draws the graph over the game, under the Info lines in the top-left corner (or beside the window while it covers that corner), with lines marking 60 and 30 fps.
  • Renderer counts: the draw calls, primitives, buffer writes and bytes written for the last frame, their average over the last second and the highest over the last 600 frames, and how many textures, render targets and depth buffers the renderer holds.
  • Limits: how much of each fixed limit is in use: the lights a view can draw (64 with shadows, 2,048 without), the lights chosen to cast shadows against the budget and those left without, the particle systems (200) and ribbons (40), the effects' shared buffers, the views the renderer keeps (32), and each of its pools of GPU resources.
  • Main view by material priority: what the main view draws, by kind (solid, skin, hair, decals, lights, transparent effects...). Views: every view the renderer keeps, with its size and how much it draws.

The renderer's counts aren't kept exactly in step with its other threads, so they can be a few short.

Timing

Both parts are off until ticked:

  • Time each render stage on the GPU: how long the graphics card takes over each stage of the frame (setting up the scene, the views before the main one, solid geometry, lighting, transparency, post-processing...) in milliseconds, with each stage's share of the frame, and the whole frame's GPU time, averaged over the last 60 frames measured while a level runs. The GPU frame time also shows on the Frame tab, the graph over the game and the Info lines. It costs about 30 timestamps a frame, and includes the Debug Menu's own drawing.
  • Time each task on the CPU: every task of the game's frame (the scripts, the AI, physics, building and sorting what to draw, the render stages...), slowest first, with its average and last time, how many times it ran in the frame and which thread ran it, and the main and worker threads' totals. A task's time includes any task it ran while it waited for another.

Memory

At the top of the tab, The game's UI memory overlay turns on the game's own overlay of the memory its UI (the menus and the HUD) takes: the game writes it in MB on the right of the screen, white while it's within budget, yellow from 29.5 MB, and red from 30.5 MB with a line under it saying the UI is out of its memory budget. It takes effect straight away, and can be switched from outside the game as perf.ui_memory_overlay; UiMemoryOverlay=1 in the settings file has it on from the start. It takes the place of Launch Game's old Enable UI Memory Overlay option. On a release of the game where it can't be found, the box is greyed out and says so.

Below it:

  • The process: the memory the game has committed and how much of it is in physical memory; how much of its 32-bit address space is used, and its largest free piece, which is what a big allocation needs (when it gets small, loading more can fail even with memory free overall); and the graphics card's memory against the budget Windows gives the game.
  • Heaps: each of the game's memory heaps, fullest first, with how much is used, its size and the most it has held. A full heap fails the next allocation from it, even with memory to spare elsewhere. Measure fragmentation adds each heap's largest free block and how fragmented it is.
  • Script entities' memory: each kind of script entity, with how many there are, the size of one, and the memory they use and have allocated.

It's read at most once a second while the tab is shown.

Streaming

Textures and models are streamed: a low-resolution copy of a texture is always in memory, and the full one streams in when a zone that uses it becomes active. The tab shows:

  • The texture and model streaming heaps: how much is used of their size and the most they've held, what's waiting to stream in or be let go, and whether streaming is busy.
  • The level's textures: how many stream, and how many of those are in at full resolution.
  • Drawn now: the textures the main view draws right now that are still at low resolution, largest first, with their full and current sizes: the blurry surfaces.

It's read at most once a second while the tab is shown.

Game

The Game group acts on the game itself:

  • Game flow: what the game is doing, its checkpoint and spawn point, the difficulty, and every level with a button to load it.
  • Saves: Don't write saves, what the game's saving is doing, and its achievements.
  • Tools: debug and level checkpoints, pausing, stepping and the game's speed, and actions on the AI.

Game Flow

  • Game flow: the game's state (in a menu, starting gameplay, playing, game over, restarting...), the level and the level asked for next, whether the level's scripts are running, paused, at the pause menu, stopped at a breakpoint or stepping, and what has paused the game.
  • Checkpoint and respawn: the checkpoint the level is at; the checkpoint in memory that a death, or Reload last checkpoint, goes back to, with its mission and how long ago it was reached; a checkpoint save waiting for the player to be able to save; and where the player spawns.
  • Difficulty: the difficulty, with buttons to change it on the spot as the pause menu does (every character takes up the new settings), and the lowest the campaign was played at, which decides its difficulty achievements. Keep the campaign's lowest difficulty (on) puts the lowest back after a change, so trying an easier difficulty doesn't cost the campaign them. While the game is paused, a change waits for it to run.
  • Levels: every level the game knows, with a filter and a Load button each, as OpenCAGE's load level. A campaign level saves as it loads, as it does in play, unless Don't write saves is on; the list says so when it's off. It takes the place of Launch Game's old Enable Level Selection, which added a list of levels to the main menu.

Saves

Tick Don't write saves and nothing the game saves reaches your saved games or the Steam Cloud: checkpoint and mission saves (save stations included), the progression (which also holds the game's settings), and the input and graphics settings. The game carries on as if each save had worked (a checkpoint still fires its outputs for a finished save), and loading still works, from what was saved before. Jumping to a checkpoint or loading a campaign level from the Debug Menu can save the game, as reaching it in play would; with this on, those saves are kept back too.

  • On from the start. Tick Don't Write Saves in Launch Game (beneath the Debug Menu box) to have it on before the game first saves. Ticked here, it only holds from then on.
  • What was kept back. The tab counts each save kept back and names the last one (Everything kept back lists them all), and with Notice on screen (on) a line at the top of the screen says so for a few seconds each time.
  • Saving: what the game's saving is doing, saves waiting, the last save this run (and whether it was kept back), the level the campaign last saved, the deaths, and the campaign's progress.

It doesn't stop achievements: see Achievements for that.

Achievements

Under Achievements, in the same tab, the game's achievements as it holds them, unlocked or not. Don't write saves doesn't stop the game awarding achievements on your Steam, GOG or Epic Games Store profile, so a debug checkpoint, a cheat or a modded level could unlock one: tick Block awards and stat writes and the game awards none, and changes none of their progress, until you untick it. BlockAchievements=1 in the settings file has it on from the start. The tab counts what was blocked and names the last one. The game may still note an achievement as won in memory, which goes into its next save, so keep Don't write saves on as well.

Tools

The Tools tab gathers the tools that act on the game rather than show it: the checkpoints, pause and game speed, a Free camera box that turns on the Cinematic group's free camera (with a button that opens its tab), the AI actions, and the Havok Visual Debugger. The player cheats that were here, Invisible to the AI and Infinite ammo, are now with the others in Characters > Player.

Checkpoints

Debug checkpoints: DebugCheckpoint entities in the level scripts that start a level part-way through. Each adds itself to the list when its part of the level activates it; levels with some include SCI_ANDROIDLAB, TECH_COMMS, HAB_AIRPORT, SCI_HUB, TECH_HUB, ENG_TOWPLATFORM and TECH_RND_HZDLAB. Press Jump beside one to jump to it. It takes the place of Launch Game's old Enable Debug Checkpoints, which added the same list to the pause menu.

Level checkpoints: below them, every Checkpoint entity the level has activated, in the order its scripts activated them, numbered, with the one the level is at marked (current). Jump goes to a checkpoint by its place in the list, so one with no name, or one sharing a name with another (there are several Save_stations), can be jumped to. Reload last checkpoint restarts from the checkpoint in memory as a death does: the level goes back to how it was when that checkpoint was reached, the player, the AI and the scripts. Nothing is read from or written to the saves for it.

Most checkpoints start a mission part: the player is spawned at the part's spawn point, and the screen fades back in once the part has loaded. A part loads only once each time the level loads, and the level's own start runs one too (with no progress saved, its ambient part), so jumping to a part that has already run leaves the screen black. Load the level again to jump to it. Jumping to a checkpoint can save the game, as reaching it in play would, unless Don't write saves is on.

Pause & Game Speed

Pause holds the whole game, its clock, the AI, physics, animation, zone streaming and the level's scripts, without the pause menu; Resume lets it go. While it's paused, Step lets exactly one frame through and Step 10 ten, one a frame. The Debug Menu keeps working meanwhile, and OpenCAGE's edits over Live Link, the difficulty and the AI actions wait until the game runs again. Pause while this window is open holds the game whenever the Debug Menu is open.

The speed slider slows the game down or speeds it up, from 0.05 to 4 times its normal speed: everything the game times runs at that rate. Reset puts it back to 1. The game's own slow-motion moments use the same scale, so they're overridden while it isn't 1, and Cap FPS still paces the frames in real time. The free camera's Time section is the same pause, step and speed.

AI

Pick a character from the dropdown, then:

  • Alert the alien to the player: every alien hears the player moving, forced past its threshold, and comes to where the player is.
  • Withdraw and Cancel withdrawal: the alien forgets what it sensed and withdraws into the vents until you cancel, as the level scripts' withdraw entity has it.
  • Menace aggressive and Menace passive: force the alien's menace into its aggressive phase (it hunts the player more closely) or its passive one (it backs off).
  • Reset: resets the selected character as the level scripts' reset entity did: its senses and memory, logic flags and timers (an alien's menace too). Reset senses and memory only makes it forget what it has sensed.
  • Logic flags: the selected character's logic flags, as the level scripts set them: Prevent all attacks, Prevent grapples, Block ambushes and kill traps, Never aggressive, Totally blind in the dark, Lock backstage stalk, Should break out, Should attack, Should hit and run, Should ambush, Ignore the player in vents, Always knows when in a vent and Mute dynamic dialogue. Hover over one for what it does.

Cinematic

The Cinematic group is a free camera for shots and video, with what HattiWatti's Cinematic Tools offered around it, and it takes their place: Launch Game no longer has Enable Cinematic Tools (see Coming from Cinematic Tools). Its camera and camera tracks are ported from Cinematic Tools, and fly the way they did. Its tabs:

  • Free Camera: turn the camera on, its lens, speeds and lock to a character, the game's pause and speed, and profiles of its settings.
  • Tracks: camera paths through nodes you place, played back smoothly.
  • Visuals: the depth of field, colour, bloom, effects and tone mapping, set in place of the level's.
  • HUD: hide the HUD, or any layer of the game's interface.
  • Cast: hold the other characters still, make the player invisible to the AI, and put the camera behind a character.
  • Screenshots: the frame as the game drew it, without the Debug Menu, saved to a file.

Free Camera

Press F8, with the Debug Menu open or closed, or tick Cinematic camera on the Free Camera tab, to fly a free camera from where the game's camera is, looking the same way with the same field of view. Close the window to fly it (see Keys & Gamepad); while the window is open it has the keys and mouse, and the camera holds still, unless Fly with this window open is ticked. Press F8 again, or Back to the game camera, to go back to the player. The line beside the box says what the camera is doing, or why it can't turn on.

While it's on, the player is frozen and the game's keyboard, mouse and gamepad are kept from it (bar Escape, for the pause menu), and the zones around the camera stream in as they would around the player. Untick Keep the game's input to play on while the camera holds where it is, follows its track or follows its character. While the pause menu or the game over screen is up, the game has its input back and the camera holds still. A level change turns it off.

  • Move the player here moves the player to the camera, and Go to the selected character puts the camera behind the character selected (in the Characters group, the Cast tab or the picker on this tab), looking at it.
  • Lens: the field of view and roll (Level straightens it).
  • Lock to a character: pick a character and tick Lock to the selected character, and the camera moves with it, kept where it is relative to the character's position and facing; flying then moves it relative to the character. Playing a track unlocks it.
  • Flying: the move, turn, roll and field of view speeds and the mouse sensitivity; Smooth mouse (on); Start from the game camera (off, it goes back to where it was left in the same level); Keep the game's input, and its gamepad and Freeze the player (all on); Fly with this window open (off), with which the keys keep flying the camera while the Debug Menu is open (not while you type in one of its boxes), the mouse turns it while you hold the right button away from the window, and the wheel zooms while the mouse is away from the window; and which Gamepad flies it (the first connected, or pad 0 to 3).
  • Time: Freeze time (pause the game), Step one frame and Time scale are the game's own pause, step and speed, the same as Game > Tools. Nothing streams in while the game is paused, so fly to your shot before pausing. Tracks play in real time whatever the time scale.
  • Profiles: save the speeds, mouse sensitivity, field of view and depth of field by name, and load or delete them. They're kept in OpenCAGE.CinematicProfiles.ini, next to the settings file in the game folder.

The free camera takes the game's camera from OpenCAGE's Viewport while Live Link's camera sync has it, and gives it back when you turn the camera off; the Viewport following the game's camera follows the free camera. As with camera sync, anything in the game that checks what the camera sees reacts to the free camera, not the player's. An environment map capture takes the camera while it runs. It won't turn on while Possess Characters has a character, and turns off when one is taken. With Unlock mouse on, the mouse moves the cursor until Unlock mouse's key (F4 by default) gives it to the game; the camera then turns with it, and the keys and a gamepad fly it meanwhile. The Free camera box on Game > Tools is the same camera.

A track is a list of nodes, each a pose of the camera at a time along the track. Played, the camera moves through them on a smooth path, easing its pace so it keeps to the nodes' times, as Cinematic Tools' tracks did.

  • Nodes: Add node where the camera is (F1 while flying), Update node to move the chosen one to where the camera is now, Delete node, Go to node, and change a node's time. A new node comes the chosen gap after the one before.

Visuals

The look of the shot, each setting set in place of the level's by ticking the box beside it. The level's own value is shown beside each, and while a box is unticked the setting follows the level's, so ticking it starts from there. Back to the level's values unticks them all.

  • Depth of field: tick Override the level's focus to set the Focal length (the longer, the stronger the blur; Cinematic Tools' DoF strength), Focus distance and F-number (the lower, the shallower the sharp part; Cinematic Tools' focus scale). The numeric pad keys change them while flying, and a track can carry them. With the game's own depth of field turned off in its graphics settings, it shows nothing, and the tab says so.
  • Colour: brightness, contrast, saturation and a red, green and blue tint.
  • Exposure and bloom: Frame scale and Frame offset (Cinematic Tools' brightness and gamma), how much bloom, and how it gathers. The game's fades to and from black go through the frame scale and offset, so no fade shows while either is set here.
  • Effects: motion blur, film grain, vignette and its colour fringe, lens distortion, sharpness, full-screen blur and chromatic aberration.
  • Tone mapping: the black, cross-over and white points, the shoulder and toe strength and the luminance scale, as in Cinematic Tools.

A value set while its box is unticked (by a command, a track or a profile) is kept for when you tick it. The Rendering group's Post tab has the engine's own switches for the post-processing.

HUD

Hide the HUD (Home while flying) hides the in-game HUD and the weapon HUD. In a challenge map it also hides the objectives, score and timer, which are a layer of their own, unless you untick Also hide the challenge mode's objectives when the HUD is hidden; hidden, they don't update, and catch up when shown again. Below, every layer of the game's interface (the motion tracker, subtitles, prompts...) can be hidden by itself. A menu hidden here stays hidden when it opens, so leave the pause menu's layer alone.

Cast

Freeze NPCs holds every character but the player idle where it stands, newly spawned ones too, until you untick it. People are held with the force idle motivation, which runs their behaviour trees' idle branch ahead of everything else, scripted orders included; the alien and the androids through their trees' debug switches, Disable All Aliens and Force Android Idle (see Tree Switches). The tab says how many are held. What it doesn't do:

  • Their senses keep running, and they still react to being hurt. An android following a script's orders carries on with them, and facehuggers can't be held.
  • Left on, it holds the next level's characters too.
  • With Tree Switches set to the selected character only, the alien and androids are only held while selected; the tab warns when it is.
  • The game keeps force idle in its saves, so a checkpoint saved while people are held brings them back idle. With Freeze NPCs still on they're let go with the rest when you untick it; otherwise, untick force idle for them in Characters > Control.

Unticked, it only undoes what it did: a character you'd set to force idle yourself, or a tree switch you'd ticked, stays as it was. For a world that stops altogether, freeze time on the Free Camera tab instead.

The tab also has Player invisible to the AI (the switch in Characters > Player), and for the character selected Camera behind it (the free camera on, 3 m behind it, looking at it), Lock the camera to it and Unlock, and Move the player to the camera.

Live Link & AI Assistants

Nearly everything in the Debug Menu has a name, so it can be worked from outside the game over Live Link, with the game started with both Debug Menu and Live Link ticked. None of it needs the window open. There are three kinds of name:

  • Switches, the tick boxes: characters.view_cones, nav.polys, game.dont_write_saves.
  • Values, the sliders, kept within their range: game.speed, nav.radius, ai.tuning.player_throw_speed.
  • Commands, for what a button does or what a tab lists, answering in plain text, a line per item: player.give with medikit,max, nav.status, inspect.pick. The command help lists every command with what it takes.

Each group above ends with a table of its names, and Names below says which group each one starts with. Most commands that act on a character act on the selected one, or on the one given as id= its unique id.

OpenCAGE works the menu this way itself: its script debugger sets and steps breakpoints through it, Select Entity Under Game Crosshair asks the World > Inspect crosshair what it's on, and Show Live States Above Nodes reads the scripts through it (see The Debug Menu Over Live Link). From the level's own scripts, a DebugMenuToggle entity sets a switch by name.

An AI assistant connected to OpenCAGE works it through runtime_utils with debug_menu and one of these as menu:

  • report (the default): whether the window is open, the group and tab in front, the selected character, the groups and tabs, the commands, every value with its number, and every switch with its state.
  • open and close the window.
  • tab brings a tab to the front by name: the tab of that name, else the first whose name contains it, else the first group whose name does, ignoring case, so Saves, debug views and Cinematic all work.
  • select selects the first character whose name, or failing that whose class, contains name, such as alien or player.
  • set ticks or unticks the switch name, as value says.
  • value sets the value name to number, kept within its range.
  • run runs the command name with argument and gives its answer, as plain text a line at a time.

The window takes up tab and select at its next frame, so report again to see them. A command that waits for the game gives up after a couple of seconds (a few that read a lot, such as physics.census, wait longer), saying it timed out (with no level running, or the game paused, say), and its work still runs when the game gets to it. With screenshot, an assistant can look at what the Debug Menu shows: the window and everything it draws over the game are in the game's picture. runtime_utils with debugger works the script debugger. A game started without the Debug Menu refuses all of these, answering that the debug menu is off in the game. launch_options with debug_menu, debug_menu_key and dont_write_saves sets the Launch Game boxes for the next start.
